## <span id="1-what-is-this-project">1. Was ist dieses Projekt?</span>

Dies ist ein **persönlicher Spielplatz** — eine Next.js-Website, die kleine Apps, Spiele und Experimente an einem Ort sammelt. Stell es dir wie eine Spielzeugkiste vor: Jede Schublade enthält ein eigenes Projekt (Memory Game, Tic-Tac-Toe, …), aber alle teilen sich dasselbe Regal (die Next.js-Site drum herum).

Das Ziel ist es, durch Bauen zu lernen: Jede Mini-App erkundet ein anderes Konzept (React-State, CSS-Animationen, Echtzeit-Datenbanken…), und die umgebende Site zeigt, wie man ein reales Next.js-Projekt organisiert.

## <span id="4-how-nextjs-routing-works">4. Wie Next.js-Routing funktioniert</span>

Next.js verwendet **Dateisystem-Routing**: Die Ordnerstruktur *ist* die URL-Struktur. Jeder Ordner, der eine `page.tsx` enthält, wird zu einer Route.

```
src/app/apps/memory-game/page.tsx       → /apps/memory-game/
src/app/apps/memory-game/play/page.tsx  → /apps/memory-game/play/
```

**`layout.tsx`-Dateien** sind besonders: Sie umhüllen alle Seiten in ihrem Ordner (und alle Unterordner). Das root `src/app/layout.tsx` umhüllt jede Seite der gesamten Site.

📖 [Next.js App Router — Routing-Grundlagen](https://nextjs.org/docs/app/building-your-application/routing)

## <span id="5-the-root-layout--wrapping-every-page">5. Das Root-Layout — jede Seite umhüllen</span>

**Datei:** `src/app/layout.tsx`

```tsx
export default function RootLayout({ children }) {
  return (
    <html lang="en" className="h-full antialiased" suppressHydrationWarning>
      <body className="flex h-full bg-zinc-50 dark:bg-black">
        <Providers>
          <div className="flex w-full">
            <Layout>{children}</Layout>
          </div>
        </Providers>
      </body>
    </html>
  )
}
```

**Was jede Zeile macht:**

- `<html suppressHydrationWarning>` — Next.js rendert das HTML zuerst auf dem Server, dann übernimmt React auf dem Client (dies nennt man *Hydration*). Das `suppressHydrationWarning`-Prop weist React an, kleine Unterschiede zwischen dem server- und clientseitig gerenderten HTML zu ignorieren — notwendig, weil `next-themes` clientseitig eine Klasse zum `<html>`-Element hinzufügt, um das Farbthema festzulegen, was der Server noch nicht kennt.
- `className="h-full antialiased"` — `h-full` lässt das HTML-Element die Viewport-Höhe ausfüllen; `antialiased` glättet Textkanten.
- `<Providers>` — Umhüllt alles in React-Context-Providern (Theme, Sprache). Mehr dazu weiter unten.
- `{children}` — Hier kommt der eigentliche Seiteninhalt. Stell es dir als Platzhalter vor, den Next.js mit der Seite füllt, die der Benutzer gerade besucht.
- `metadata` — Das exportierte `metadata`-Objekt legt den Browser-Tab-Titel und die Beschreibung fest. Jede Seite kann es mit ihrem eigenen `metadata`-Export überschreiben.

📖 [Next.js Layouts](https://nextjs.org/docs/app/building-your-application/routing/layouts-and-templates)
📖 [React-Hydration erklärt](https://react.dev/reference/react-dom/client/hydrateRoot)

## <span id="6-providers--global-context-for-the-whole-app">6. Provider — globaler Kontext für die gesamte App</span>

**Datei:** `src/app/providers.tsx`

Provider sind React-Komponenten, die Daten für *alle* ihre Kinder zugänglich machen, egal wie tief sie verschachtelt sind, ohne Props manuell weitergeben zu müssen. Stell es dir wie eine Radioübertragung vor: Der Provider ist der Sender, und jede Komponente, die sich einschaltet (mit `useContext`), kann das Signal empfangen.

Diese Datei richtet drei Provider ein:

### <span id="appcontext--remembers-the-previous-page">AppContext — merkt sich die vorherige Seite</span>

```tsx
export const AppContext = createContext<{ previousPathname?: string }>({})
```

Dieser Context speichert die URL der Seite, auf der der Benutzer *vor* der aktuellen war. Das Zurück-Button-Verhalten in `AppLayout` nutzt ihn, um zu entscheiden, ob ein "← Zurück"-Link angezeigt werden soll.

```tsx
let pathname = usePathname()
let previousPathname = usePrevious(pathname)
```

`usePrevious` ist ein benutzerdefinierter Hook, der `useRef` verwendet, um den Wert des *letzten* Renders zu merken. Bei jeder Navigation ist `pathname` die neue URL; `ref.current` (der vorherige Wert) wird zur alten URL.

### <span id="themeprovider--darklight-mode">ThemeProvider — Dunkel-/Hellmodus</span>

```tsx
<ThemeProvider attribute="class" disableTransitionOnChange>
```

`next-themes` umhüllt die App und fügt `<html>` eine `dark`-Klasse hinzu, wenn der Dunkelmodus aktiv ist. Tailwind verwendet dann `dark:`-Präfix-Klassen, um dunkle Styles anzuwenden. `disableTransitionOnChange` verhindert ein hässliches Farbaufblitzen, wenn sich das Theme beim ersten Laden ändert.

### <span id="languageprovider--ende-translations">LanguageProvider — EN/DE-Übersetzungen</span>

Ausführlich behandelt in [Abschnitt 10](#10-internationalisation-i18n--english--german).

### <span id="themewatcher--syncs-to-os-preference">ThemeWatcher — synchronisiert mit der Betriebssystem-Einstellung</span>

```tsx
function ThemeWatcher() {
  let { resolvedTheme, setTheme } = useTheme()

  useEffect(() => {
    let media = window.matchMedia('(prefers-color-scheme: dark)')

    function onMediaChange() {
      let systemTheme = media.matches ? 'dark' : 'light'
      if (resolvedTheme === systemTheme) {
        setTheme('system')
      }
    }

    onMediaChange()
    media.addEventListener('change', onMediaChange)
    return () => media.removeEventListener('change', onMediaChange)
  }, [resolvedTheme, setTheme])

  return null
}
```

Wenn der Benutzer sein Betriebssystem-Theme ändert, während die App geöffnet ist (z. B. von dunkel zu hell), erkennt diese Komponente die Änderung über `window.matchMedia` und wechselt das Theme zurück zu `'system'`, damit es dem Betriebssystem folgt. Sie rendert nichts (`return null`) — sie führt nur Seiteneffekte aus.

📖 [React Context](https://react.dev/learn/passing-data-deeply-with-context)
📖 [useRef und usePrevious-Muster](https://react.dev/reference/react/useRef)

## <span id="7-shared-components">7. Gemeinsame Komponenten</span>

### <span id="layout">Layout</span>

**Datei:** `src/components/Layout.tsx`

```tsx
export function Layout({ children }) {
  return (
    <>
      {/* Festes weisses Panel hinter dem Inhalt */}
      <div className="fixed inset-0 flex justify-center sm:px-8">
        <div className="flex w-full max-w-7xl lg:px-8">
          <div className="w-full bg-white ring-1 ring-zinc-100 dark:bg-zinc-900 dark:ring-zinc-300/20" />
        </div>
      </div>
      {/* Scrollbarer Inhalt darüber */}
      <div className="relative flex w-full flex-col pt-20">
        <Header />
        <main className="flex-auto">{children}</main>
        <Footer />
      </div>
    </>
  )
}
```

Zwei Ebenen sind übereinander gestapelt:
1. Ein `fixed` weisses/dunkles Panel, das beim Scrollen an Ort und Stelle bleibt — es erzeugt den visuellen "Karten"-Effekt in der Mitte der Seite.
2. Der eigentliche scrollbare Inhalt: Header → Hauptbereich → Footer.

`pt-20` (padding-top: 5rem) schiebt den Inhalt nach unten, um Platz für den festen Header zu schaffen.

### <span id="header">Header</span>

**Datei:** `src/components/Header.tsx`

Der Header ist `position: fixed`, damit er beim Scrollen oben bleibt. Er enthält:

- **Avatar** — ein React-Logo, das zurück zur Startseite verlinkt.
- **Desktop-Navigation** — eine pill-förmige Navigationsleiste mit Home- und Journal-Links, nur auf `md`-Bildschirmen (768px+) sichtbar.
- **Mobile Navigation** — ein "Menü"-Button, der auf kleinen Bildschirmen ein `<Popover>`-Overlay (von Headless UI) öffnet. Verwendet `md:hidden`, um sich auf dem Desktop zu verstecken.
- **Sprach-Umschalter** — wechselt zwischen EN und DE. Verwendet den `mounted`-State, um einen Hydration-Mismatch zu verhindern: Auf dem Server gibt es kein localStorage, daher rendert die Komponente so, als ob das Locale unbekannt ist, und aktualisiert sich clientseitig nach dem Mounten.
- **Theme-Umschalter** — wechselt Dunkel-/Hellmodus. Dasselbe `mounted`-Muster aus demselben Grund.

**Das `mounted`-Muster erklärt:**

```tsx
const [mounted, setMounted] = useState(false)

useEffect(() => {
  setMounted(true)   // läuft nur im Browser, nach dem ersten Render
}, [])

return <button aria-label={mounted ? `Switch to ${otherTheme}` : 'Toggle theme'}>
```

Der Server rendert HTML ohne Kenntnis des aktuellen Themes oder der Sprache. Wenn das `aria-label` des Buttons auf dem Server "Switch to light" sagt, aber der Browser den Dunkelmodus hat, bemerkt React den Mismatch und gibt eine Warnung aus. Mit `mounted` rendert der Button ein neutrales Label auf dem Server und aktualisiert sich, sobald er sicher im Browser ist.

📖 [Headless UI Popover](https://headlessui.com/react/popover)

### <span id="footer">Footer</span>

**Datei:** `src/components/Footer.tsx`

Einfacher Footer mit einer Copyright-Zeile und dem `useTranslation`-Hook für den "Erstellt mit"-Text. `new Date().getFullYear()` zeigt automatisch das aktuelle Jahr an.

### <span id="container">Container</span>

**Datei:** `src/components/Container.tsx`

Ein wiederverwendbarer zentrierter Inhalts-Wrapper. Er ist in Schichten aufgebaut — eine äussere Komponente fügt horizontalen Abstand hinzu; eine innere begrenzt die Breite und zentriert sie:

```
ContainerOuter → max-width: 7xl (80rem), horizontaler Abstand
  ContainerInner → max-width: 5xl (64rem), mehr Abstand
    Dein Inhalt
```

Als wiederverwendbare Komponente musst du die maximale Breite nur an einer Stelle ändern, wenn du das Layout neu gestaltest.

### <span id="card">Card</span>

**Datei:** `src/components/Card.tsx`

Die `Card`-Komponente wird auf der Startseite verwendet, um jede App anzuzeigen. Sie verwendet ein Muster namens **Compound Components** — eine Gruppe verwandter Unterkomponenten, die auf demselben Objekt leben:

```tsx
<Card>
  <Card.Title href="/apps/memory-game">Memory Game</Card.Title>
  <Card.Description>Ein Karten-Matching-Spiel…</Card.Description>
  <Card.Cta>Mehr lesen</Card.Cta>
  <Card.Eyebrow>14. März 2025</Card.Eyebrow>
</Card>
```

**Der Hover-Effekt erklärt:**

```tsx
// In Card.Link:
<div className="absolute -inset-x-4 -inset-y-6 z-0 scale-95 bg-zinc-50
  opacity-0 transition group-hover:scale-100 group-hover:opacity-100
  sm:-inset-x-6 sm:rounded-2xl dark:bg-zinc-800/50" />
```

Dies ist ein unsichtbares `div`, das sich beim Hover auf den Kartenbereich ausdehnt. Die `group`-Klasse am Elternelement sagt Tailwind: "Wenn das Elternelement gehovert wird, wende `group-hover:`-Styles auf Kinder an." Das div geht beim Hover von `scale-95 opacity-0` → `scale-100 opacity-100`, was einen sanften "Pop"-Hintergrundeffekt erzeugt.

📖 [Tailwind CSS group-hover](https://tailwindcss.com/docs/hover-focus-and-other-states#styling-based-on-parent-state)

## <span id="8-how-app-metadata-is-loaded--libappsts">8. Wie App-Metadaten geladen werden — `lib/apps.ts`</span>

**Datei:** `src/lib/apps.ts`

Dies ist ein **serverseitiges** Hilfsprogramm (es läuft zur Build-Zeit, nicht im Browser). Es durchsucht das Verzeichnis `src/app/apps/`, findet jeden Ordner mit einer `page.en.mdx`-Datei, importiert diese Datei dynamisch und extrahiert das exportierte `app`-Objekt daraus.

```ts
export async function getAllApps() {
  let appsDir = path.join(process.cwd(), 'src/app/apps')
  let entries = fs.readdirSync(appsDir, { withFileTypes: true })

  let appFilenames = entries
    .filter(e => e.isDirectory() && fs.existsSync(path.join(appsDir, e.name, 'page.en.mdx')))
    .map(e => `${e.name}/page.en.mdx`)

  let apps = await Promise.all(appFilenames.map(importApp))
  return apps.sort((a, z) => +new Date(z.date) - +new Date(a.date))
}
```

**Warum dieses Design?** Die Metadaten für jede App (Titel, Beschreibung, Tech-Tags, Datum) befinden sich in derselben Datei wie der geschriebene Inhalt der App. Das bedeutet: Wenn du eine neue App hinzufügst, erstellst du nur eine Datei, und die Startseite nimmt sie automatisch auf — keine manuelle Registrierung erforderlich.

**Analogie:** Es ist wie ein Buch, das automatisch sein eigenes Inhaltsverzeichnis generiert, indem es die Kapitelüberschriften scannt, anstatt das Inhaltsverzeichnis manuell schreiben zu müssen.

📖 [Node.js fs-Modul](https://nodejs.org/api/fs.html)
📖 [Dynamische Imports in JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import)

## <span id="9-mdx--writing-content-like-code">9. MDX — Inhalte wie Code schreiben</span>

**MDX** ist Markdown mit Superkräften: Du kannst React-Komponenten darin einbetten. Jede App hat eine `page.en.mdx`-Datei, die zwei Zwecke gleichzeitig erfüllt:

```jsx
export const app = {          ← JavaScript-Export (Metadaten)
  title: 'Memory Game',
  description: '...',
  tech: ['React', 'TypeScript', 'useState', 'useEffect'],
  date: '2025-03-14',
  category: 'games',
}

Ein Gedächtnis-Kartenspiel, bei dem...   ← Normaler Markdown-Prosatext

## Was ich gelernt habe                  ← Markdown-Überschrift

- Spielstate mit `useState` verwalten
```

Der `app`-Export ist das, was `lib/apps.ts` sammelt. Der Markdown-Text wird als Hauptteil der Beschreibungsseite der App gerendert.

**Konfiguration** (`next.config.mjs`):

```js
const withMDX = nextMDX({
  extension: /\.mdx?$/,
  options: {
    remarkPlugins: ['remark-gfm'],      // aktiviert Tabellen, Durchstreichen etc.
    rehypePlugins: ['@mapbox/rehype-prism'], // Syntaxhervorhebung in Codeblöcken
  },
})
```

MDX-Dateien durchlaufen eine Pipeline: Sie werden als Markdown geparst, von `remark` in HTML umgewandelt und dann von MDX in React-Komponenten umgewandelt. Die Plugins fügen jeder Stufe zusätzliche Funktionen hinzu.

📖 [MDX-Dokumentation](https://mdxjs.com/docs/)
📖 [remark-gfm (GitHub Flavored Markdown)](https://github.com/remarkjs/remark-gfm)

## <span id="10-internationalisation-i18n--english--german">10. Internationalisierung (i18n) — Englisch & Deutsch</span>

**Datei:** `src/i18n/index.tsx`

Die Site unterstützt Englisch und Deutsch. Alle sichtbaren Texte sind als Schlüssel-Wert-Paare in Übersetzungsdateien gespeichert, und Komponenten suchen Texte nach Schlüssel, anstatt sie fest einzucodieren.

**Übersetzungsdateien** (`src/i18n/translations/en.ts`, `de.ts`):

```ts
// en.ts
'memory.moves': 'Moves: {{count}}',
'memory.youWon': 'You won in {{moves}} moves!',

// de.ts
'memory.moves': 'Züge: {{count}}',
'memory.youWon': 'Du hast in {{moves}} Zügen gewonnen!',
```

**Die `LanguageProvider`-Komponente:**

```tsx
export function LanguageProvider({ children }) {
  const [locale, setLocaleState] = useState<Locale>('en')

  useEffect(() => {
    setLocaleState(getInitialLocale())  // liest localStorage oder Browser-Sprache
  }, [])

  const t = useCallback((key, params) => {
    let text = translations[locale][key] ?? translations['en'][key] ?? key
    if (params) {
      Object.entries(params).forEach(([k, v]) => {
        text = text.replace(new RegExp(`\\{\\{${k}\\}\\}`, 'g'), String(v))
      })
    }
    return text
  }, [locale])

  return <LanguageContext.Provider value={{ locale, setLocale, t }}>
    {children}
  </LanguageContext.Provider>
}
```

- `getInitialLocale()` prüft `localStorage` auf eine gespeicherte Einstellung und fällt dann auf die Spracheinstellung des Browsers zurück (`navigator.language`).
- Die `t()`-Funktion nimmt einen Schlüssel und optionale Parameter. Sie findet die Zeichenkette in den Übersetzungen des aktuellen Locales und ersetzt dann `{{Platzhalter}}` durch echte Werte. Zum Beispiel: `t('memory.youWon', { moves: 14 })` → `"Du hast in 14 Zügen gewonnen!"`.
- `useCallback` memoisiert die `t`-Funktion, damit sie nicht bei jedem Render neu erstellt wird (nur wenn sich `locale` ändert), was ein wichtiges Performance-Detail ist.

**Übersetzungen in Komponenten verwenden:**

```tsx
let { t } = useTranslation()

<div>{t('memory.moves', { count: moves })}</div>
```

📖 [useCallback](https://react.dev/reference/react/useCallback)

## <span id="11-mini-app-tic-tac-toe">11. Mini-App: Tic-Tac-Toe</span>

**Datei:** `src/components/games/TicTacToe.tsx`

Dies war das erste gebaute Projekt — basierend auf dem [offiziellen React-Tutorial](https://react.dev/learn/tutorial-tic-tac-toe). Es ist ein grossartiger Einstieg, da es mehrere grundlegende React-Muster einführt.

### <span id="component-structure">Komponentenstruktur</span>

Das Spiel ist in drei Komponenten aufgeteilt:

```
TicTacToe (oberste Ebene)
  └── Board (das 3×3-Raster + Statustext)
        └── Square × 9 (einzelne anklickbare Zellen)
```

Jede Komponente kennt nur ihre eigene Verantwortlichkeit. `Square` rendert nur einen Button. `Board` rendert das Raster und berechnet den Gewinner. `TicTacToe` verwaltet die Historie und die Zeitreise.

### <span id="state-immutable-history">State: unveränderliche Historie</span>

```tsx
const [history, setHistory] = useState<(string | null)[][]>([Array(9).fill(null)])
const [currentMove, setCurrentMove] = useState(0)
```

`history` ist ein Array von Brettzuständen. Jedes Element ist ein Array von 9 Zellen (`null | 'X' | 'O'`). Wenn ein Zug gemacht wird, wird ein **neues** Array erstellt — das alte wird nie verändert:

```tsx
function handlePlay(nextSquares) {
  // Verwerfe zukünftige Züge, wenn der Spieler in der Zeit zurückgesprungen ist
  const nextHistory = [...history.slice(0, currentMove + 1), nextSquares]
  setHistory(nextHistory)
  setCurrentMove(nextHistory.length - 1)
}
```

**Warum Unveränderlichkeit?** Wenn du das vorhandene Array direkt veränderst, bemerkt React die Änderung möglicherweise nicht und rendert nicht erneut. Noch wichtiger: Das Beibehalten aller vergangenen Zustände macht die Zeitreise-Funktion trivial: Zu Zug 3 zu springen bedeutet nur, `currentMove = 3` zu setzen und `history[3]` zu lesen.

**Analogie:** Es ist wie das Fotokopieren eines Dokuments vor dem Bearbeiten, anstatt es auszuradieren und neu zu schreiben. Du hast immer alle alten Versionen.

### <span id="winner-detection">Gewinnererkennung</span>

```tsx
function calculateWinner(squares) {
  const lines = [
    [0, 1, 2], [3, 4, 5], [6, 7, 8], // Zeilen
    [0, 3, 6], [1, 4, 7], [2, 5, 8], // Spalten
    [0, 4, 8], [2, 4, 6],             // Diagonalen
  ]
  for (const [a, b, c] of lines) {
    if (squares[a] && squares[a] === squares[b] && squares[a] === squares[c]) {
      return squares[a]
    }
  }
  return null
}
```

Alle 8 möglichen Gewinnkombinationen sind fest eincodiert. Für jede Kombination gilt: Wenn alle drei Felder denselben Nicht-Null-Wert haben, wird dieser Wert (`'X'` oder `'O'`) als Gewinner zurückgegeben.

📖 [Offizielles React Tic-Tac-Toe-Tutorial](https://react.dev/learn/tutorial-tic-tac-toe)

## <span id="12-mini-app-memory-game-deep-dive">12. Mini-App: Memory Game (tiefer Einblick)</span>

**Datei:** `src/components/games/MemoryGame.tsx`

Dies ist das komplexeste Solo-Spiel im Projekt. Es führt **CSS-3D-Animationen**, **asynchrone Logik mit Bereinigung** und **hydration-sichere Initialisierung** ein.

### <span id="the-card-data-type">Der `Card`-Datentyp</span>

```tsx
interface Card {
  id: number        // eindeutig für alle 12 Karten
  imageId: number   // geteilt zwischen den zwei passenden Karten (0–5)
  imageSrc: string  // Pfad zum SVG-Bild
  isFlipped: boolean
  isMatched: boolean
}
```

**`id` vs `imageId`:** Zwei Karten können dieselbe `imageId` haben (sie sind ein Paar), müssen aber unterschiedliche `id`s haben (damit React sie unterscheiden kann). Zum Beispiel haben die beiden Herz-Karten `imageId: 1` und `id: 2` und `id: 3`.

### <span id="creating-and-shuffling-the-deck">Das Deck erstellen und mischen</span>

```tsx
const CARD_IMAGES = [
  '/images/memory-game/star.svg',
  '/images/memory-game/heart.svg',
  // … insgesamt 6
]

function createDeck(): Card[] {
  return CARD_IMAGES.flatMap((src, imageId) => [
    { id: imageId * 2,     imageId, imageSrc: src, isFlipped: false, isMatched: false },
    { id: imageId * 2 + 1, imageId, imageSrc: src, isFlipped: false, isMatched: false },
  ])
}
```

`Array.flatMap` iteriert über die 6 Bilder und gibt für jedes *zwei* Kartenobjekte zurück (das Paar), dann flacht es das Array von Paaren in ein einziges flaches Array von 12 Karten ab.

```tsx
function shuffleDeck(cards: Card[]): Card[] {
  const shuffled = [...cards]   // Kopie, damit das Original nicht verändert wird
  for (let i = shuffled.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1))
    ;[shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]]
  }
  return shuffled
}
```

Dies ist der **Fisher-Yates-Shuffle** — der Standardalgorithmus für ein faires zufälliges Mischen. Er arbeitet rückwärts durch das Array und tauscht jedes Element mit einem zufälligen Element davor aus (einschliesslich sich selbst). Jede mögliche Reihenfolge von 12 Karten ist gleich wahrscheinlich.

**Analogie:** Stell dir 12 Karten verdeckt in einer Reihe vor. Du beginnst von rechts, nimmst eine zufällige Karte aus den verbleibenden unsortierten Karten links und tauschst sie an die Position. Wiederhole bis fertig.

📖 [Fisher-Yates-Shuffle erklärt](https://en.wikipedia.org/wiki/Fisher%E2%80%93Yates_shuffle)

### <span id="state">State</span>

```tsx
const [cards, setCards] = useState<Card[]>([])
const [selectedCards, setSelectedCards] = useState<number[]>([])
const [moves, setMoves] = useState(0)
const [isChecking, setIsChecking] = useState(false)
const timeoutRef = useRef<ReturnType<typeof setTimeout> | null>(null)
```

- `cards` — das vollständige Array von 12 Kartenobjekten.
- `selectedCards` — ein Array von 0, 1 oder 2 *Indizes* (Positionen im `cards`-Array) der aktuell umgedrehten, aber noch nicht ausgewerteten Karten.
- `moves` — Anzahl der Paare, die der Spieler versucht hat.
- `isChecking` — `true` während der 1-Sekunden-Verzögerung, bei der ein Mismatch angezeigt wird. Blockiert neue Klicks.
- `timeoutRef` — speichert die ID des aktiven `setTimeout`, damit es bei Bedarf abgebrochen werden kann (z. B. beim Start eines neuen Spiels mitten in der Verzögerung).

**Warum `useRef` für den Timeout statt `useState`?** `useRef` speichert einen Wert, der zwischen Renders bestehen bleibt, aber *keine* Neuerenderung auslöst, wenn er sich ändert. Die Timeout-ID ist rein operativ — die UI muss sich nicht aktualisieren, wenn sie sich ändert.

📖 [useState](https://react.dev/reference/react/useState)
📖 [useRef](https://react.dev/reference/react/useRef)

### <span id="hydration-safe-initialisation">Hydration-sichere Initialisierung</span>

```tsx
const [cards, setCards] = useState<Card[]>([])   // startet LEER

useEffect(() => {
  setCards(shuffleDeck(createDeck()))             // gemischt nur im Browser
  return () => {
    if (timeoutRef.current) clearTimeout(timeoutRef.current)  // Bereinigung
  }
}, [])
```

Das Deck wird *leer* initialisiert und nur innerhalb von `useEffect` gefüllt. Hier ist der Grund:

Next.js rendert das Seiten-HTML auf dem Server, bevor der Browser JavaScript ausführt. `Math.random()` würde auf dem Server ein anderes Misch-Ergebnis produzieren als im Browser, was einen **Hydration-Mismatch-Fehler** verursachen würde — React würde bemerken, dass das serverseitig Gerenderte nicht mit dem übereinstimmt, was es im Browser zu rendern versucht.

Indem mit `[]` begonnen wird (gleich auf Server und Browser) und erst innerhalb von `useEffect` gemischt wird (das nur im Browser läuft), stimmen beide Seiten beim Ausgangszustand überein.

Das `return () => { clearTimeout() }` ist die **Bereinigungsfunktion**. Sie läuft, wenn die Komponente von der Seite entfernt wird, und verhindert einen Absturz durch einen Timeout, der nach dem Entfernen der Komponente auslöst.

📖 [useEffect und Bereinigung](https://react.dev/reference/react/useEffect#parameters)
📖 [Hydration-Fehler in Next.js](https://nextjs.org/docs/messages/react-hydration-error)

### <span id="handling-card-clicks">Kartenklicks verarbeiten</span>

```tsx
function handleCardClick(index: number) {
  if (isChecking) return                                   // 1. blockiert?
  if (cards[index].isFlipped || cards[index].isMatched) return // 2. bereits aktiv?
  if (selectedCards.length >= 2) return                    // 3. schon zwei ausgewählt?

  // Klickende Karte umdrehen
  const newCards = cards.map((card, i) =>
    i === index ? { ...card, isFlipped: true } : card
  )
  const newSelected = [...selectedCards, index]

  setCards(newCards)
  setSelectedCards(newSelected)

  if (newSelected.length === 2) {
    setMoves(m => m + 1)
    const [first, second] = newSelected

    if (newCards[first].imageId === newCards[second].imageId) {
      // ✅ Treffer!
      setCards(newCards.map((card, i) =>
        i === first || i === second ? { ...card, isMatched: true } : card
      ))
      setSelectedCards([])
    } else {
      // ❌ Kein Treffer — nach 1 Sekunde zurückdrehen
      setIsChecking(true)
      timeoutRef.current = setTimeout(() => {
        setCards(prev => prev.map((card, i) =>
          i === first || i === second ? { ...card, isFlipped: false } : card
        ))
        setSelectedCards([])
        setIsChecking(false)
      }, 1000)
    }
  }
}
```

**Schritt für Schritt:**

1. **Guard Clauses** am Anfang verhindern ungültige Klicks. Diese frühen `return`-Anweisungen werden Guard Clauses genannt — sie beenden die Funktion sofort, wenn eine Bedingung nicht erfüllt ist, und halten die Hauptlogik am Ende uneingerückt und leicht lesbar.

2. **Unveränderliches Update**: `cards.map(...)` erstellt ein *neues* Array mit dem `isFlipped`-Wert der angeklickten Karte auf `true` gesetzt. Das ursprüngliche Array wird nie verändert.

3. **Trefferprüfung**: Beide Karten haben dieselbe `imageId`? → markiere sie als `isMatched: true`, leere `selectedCards`.

4. **Mismatch**: Setze `isChecking`, um neue Klicks zu blockieren, dann nutze `setTimeout`, um die Karten nach 1000ms zurückzudrehen. Innerhalb des Timeouts verwendet `setCards(prev => ...)` die **funktionale Update-Form** von setState — `prev` ist garantiert der *aktuelle* State zum Zeitpunkt des Auslösens des Timeouts, nicht der veraltete State, der beim Erstellen des Timeouts erfasst wurde.

📖 [Funktionale Updates in setState](https://react.dev/reference/react/useState#updating-state-based-on-the-previous-state)

### <span id="the-card-flip-animation">Die Karten-Dreh-Animation</span>

Jede Karte ist eine 3D-Struktur aus drei verschachtelten `div`s:

```
div.perspective          ← Richtet die 3D-Kamera ein
  div.preserve-3d        ← Dreht sich beim Umdrehen
    div.back-face        ← Die "?"-Seite
    div.front-face       ← Die Bildseite
```

```tsx
{/* Äusserer Wrapper — stellt die 3D-Perspektive bereit */}
<div className="h-24 w-20 cursor-pointer [perspective:1000px] sm:h-32 sm:w-28">

  {/* Mittlere Ebene — das ist, was sich tatsächlich dreht */}
  <div className={clsx(
    'relative h-full w-full transition-transform duration-500 [transform-style:preserve-3d]',
    (card.isFlipped || card.isMatched) && '[transform:rotateY(180deg)]',
  )}>

    {/* Rückseite — sichtbar wenn NICHT umgedreht */}
    <div className="absolute inset-0 ... [backface-visibility:hidden]">?</div>

    {/* Vorderseite — sichtbar wenn umgedreht */}
    <div className="absolute inset-0 ... [backface-visibility:hidden] [transform:rotateY(180deg)]">
      <img src={card.imageSrc} />
    </div>
  </div>
</div>
```

**Wie CSS-3D-Drehung funktioniert:**

- `perspective: 1000px` — legt fest, wie weit die "Kamera" entfernt ist. Je grösser der Wert, desto weniger dramatisch ist die Perspektivverzerrung. Ohne dies würde die Drehung flach aussehen.
- `transform-style: preserve-3d` — teilt dem Browser mit, dass Kinder dieses Elements im 3D-Raum existieren sollen (anstatt auf eine 2D-Ebene abgeflacht zu werden).
- `backface-visibility: hidden` — versteckt eine Seite, wenn sie mehr als 90° vom Betrachter weg gedreht ist. Ohne dies würden beide Seiten gleichzeitig sichtbar sein.
- Die **Vorderseite** startet vorgedreht um 180° (`rotateY(180deg)`). Wenn die mittlere Ebene auf 180° dreht, heben sich Vorder- und Rückseite auf — die Vorderseite erscheint gerade von vorne, die Rückseite zeigt jetzt weg.
- Die Drehung wird ausgelöst, indem `[transform:rotateY(180deg)]` zur mittleren Ebene hinzugefügt wird. `transition-transform duration-500` animiert es über 500ms.

**Analogie:** Stell dir eine Tür mit einem Poster auf jeder Seite vor. Die Tür ist zunächst geschlossen — du siehst Seite A. Du drehst die Tür um 180° und siehst jetzt Seite B. Jede Seite hat ein Schild mit der Aufschrift "Zeig dich nur, wenn du dem Betrachter zugewandt bist" (`backface-visibility: hidden`).

📖 [CSS 3D transforms (MDN)](https://developer.mozilla.org/en-US/docs/Web/CSS/transform-function/rotateY)
📖 [CSS backface-visibility (MDN)](https://developer.mozilla.org/en-US/docs/Web/CSS/backface-visibility)

### <span id="placeholder-cards-during-ssr">Platzhalterkarten während SSR</span>

```tsx
{cards.length === 0
  ? Array.from({ length: totalCards }, (_, i) => (
      <div key={i} className="h-24 w-20 sm:h-32 sm:w-28">
        <div className="... bg-violet-500">?</div>
      </div>

}
```

Da `cards` auf dem Server als `[]` startet, rendert dies 12 verdeckte Platzhalterkarten — die richtige Anzahl, in der richtigen Grösse. Dies verhindert einen Layout-Versatz, wenn die echten Karten nach der Hydration erscheinen.

### <span id="win-detection">Gewinnererkennung</span>

```tsx
const matchedPairs = cards.filter(c => c.isMatched).length / 2
const isGameWon = matchedPairs === CARD_IMAGES.length

{isGameWon && (
  <div className="... text-green-700">

```

## <span id="15-multiplayer--real-time-with-supabase">15. Multiplayer — Echtzeit mit Supabase</span>

**Dateien:** `src/lib/multiplayer.ts`, `src/components/multiplayer/`

Sowohl Memory Game als auch Tic-Tac-Toe haben Multiplayer-Modi, bei denen zwei Spieler in Echtzeit aus verschiedenen Browsern spielen können. Dies wird durch **Supabase** ermöglicht — eine Open-Source-Firebase-Alternative, die eine PostgreSQL-Datenbank mit einer Echtzeit-Abonnement-Funktion bereitstellt.

### <span id="how-the-room-system-works">Wie das Raumsystem funktioniert</span>

**Analogie:** Stell es dir wie eine Online-Spiellobby vor. Spieler A erstellt einen Raum und bekommt einen 6-stelligen Code (z. B. `XK9P2M`). Spieler B gibt diesen Code ein, um beizutreten. Sobald beide drin sind, startet das Spiel und beide Spieler sehen jeden Zug sofort.

### <span id="room-lifecycle">Raum-Lebenszyklus</span>

```
Spieler A: createRoom()    → fügt eine Zeile in die 'rooms'-Tabelle ein
                             room.status = 'waiting', room.player_a = 'alice'

Spieler B: findRoomByCode()  → liest die Zeile nach Code
           joinRoom()        → aktualisiert room.player_b = 'bob', status = 'playing'

Beide:   subscribeToRoom()   → horcht auf Änderungen via Supabase Realtime
```

### <span id="room-code-generation">Raumcode-Generierung</span>

```ts
function generateRoomCode(): string {
  const chars = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789'
  let code = ''
  for (let i = 0; i < 6; i++) {
    code += chars[Math.floor(Math.random() * chars.length)]
  }
  return code
}
```

Das Alphabet schliesst bewusst visuell verwechselbare Zeichen aus: `I`, `O`, `1`, `0` (schwer voneinander zu unterscheiden). Dies ist ein durchdachtes UX-Detail — der Code ist dazu gedacht, von einem Menschen eingetippt zu werden.

### <span id="real-time-subscriptions">Echtzeit-Abonnements</span>

```ts
export function subscribeToRoom(
  roomId: string,
  onUpdate: (room: Room) => void
): RealtimeChannel {
  return supabase
    .channel(`room:${roomId}`)
    .on('postgres_changes', {
      event: 'UPDATE',
      schema: 'public',
      table: 'rooms',
      filter: `id=eq.${roomId}`,
    }, payload => {
      onUpdate(payload.new as Room)
    })
    .subscribe()
}
```

Supabase Realtime verwendet **PostgreSQLs logische Replikation**, um Zeilenänderungen zu erkennen und sie über WebSockets an verbundene Clients zu senden. Wenn Spieler A einen Zug macht (der die `rooms`-Tabelle aktualisiert), löst das Abonnement von Spieler B sofort aus — kein Polling erforderlich.

### <span id="game-state-sync">Spielstate-Synchronisation</span>

Der gesamte Spielstate (alle Kartenpositionen, Umdreh-Zustände, Punktestände) wird als JSON-Spalte in der `rooms`-Tabelle gespeichert. Wenn ein Spieler einen Zug macht:
1. Berechnet er den neuen Spielstate lokal.
2. Ruft `updateGameState(roomId, newState)` auf, um ihn in Supabase zu schreiben.
3. Die `subscribeToRoom`-Callbacks beider Spieler lösen mit dem neuen State aus.
4. Beide UIs werden neu gerendert.

📖 [Supabase Realtime-Dokumentation](https://supabase.com/docs/guides/realtime)
📖 [WebSockets erklärt](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)

"paths": { "@/*": ["./src/*"] }
